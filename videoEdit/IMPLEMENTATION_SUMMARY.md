# 固定人脸视频剪辑工具实施说明

日期：2026 年 9 月 7 日

## 项目目标

使用 `faces` 中的儿童人脸样本，识别 `input` 中视频里儿童出现的时间。每次出现导出一个独立 MP4，源视频不作修改。

当前默认规则为：出现前 2 秒、后 2 秒，输出片段之间不重复。

## 当前实现

| 文件 | 说明 |
| --- | --- |
| `face_clip.py` | 主处理脚本，负责识别、分段、去重、导出和报告。 |
| `config.json` | 人脸识别、分段和视频导出参数。 |
| `test_face_clip.py` | 分段、前后扩展和去重逻辑的单元测试。 |
| `README.md` | 日常使用说明。 |
| `output_2s_no_overlap` | 当前规则的输出目录。 |

本机版本采用 OpenCV YuNet 检测人脸，SFace 生成人脸特征。该方案适合当前 i5-12600K、32GB 内存、无 NVIDIA 独显的电脑，并可在 Python 3.14 环境直接运行。

处理流程：

1. 读取人脸样本并生成归一化特征。
2. 按 `sample_fps` 抽取视频帧。
3. 检测帧中人脸并计算与目标人脸的相似度。
4. 把相邻命中聚合为一次出现。
5. 增加前后上下文。
6. 对相邻输出时间窗执行去重裁切。
7. 用 FFmpeg 导出视频和 JSON 报告。

## 前后上下文和去重

旧配置为前后各 5 秒。假设两次出现分别是 10 至 20 秒、22 至 30 秒：

```text
第一次输出：5 至 25 秒
第二次输出：17 至 35 秒
```

两个文件会同时包含 17 至 25 秒，所以会有重复画面。

当前配置：

```json
"before_seconds": 2.0,
"after_seconds": 2.0,
"clip_overlap_strategy": "trim"
```

先给每次出现增加前后 2 秒。若相邻片段不重叠，两个片段都保留完整上下文；若仍重叠，就在交叠区中点切开。

```text
第一次候选片段：8 至 14 秒
第二次候选片段：11 至 17 秒
重叠区域：11 至 14 秒
最终片段：8 至 12.5 秒，12.5 至 17 秒
```

因此不同输出文件不会含有同一时间段。代价是两次出现非常接近时，某一侧上下文会少于 2 秒；这是“完整上下文”和“绝不重复”无法同时满足时的必要取舍。

## config.json 参数说明

| 参数 | 当前值 | 作用 | 调整建议 |
| --- | --- | --- | --- |
| `reference_faces_dir` | `faces` | 目标人脸样本目录。 | 可放同一人的多张清晰正脸。 |
| `input_dir` | `input` | 输入视频目录。 | 可改为绝对路径。 |
| `output_dir` | `output_2s_no_overlap` | 新规则的输出目录。 | 历史结果仍在 `output`。 |
| `model_dir` | `.models` | ONNX 模型目录。 | EXE 打包时应一起携带。 |
| `recognition_mode` | `balanced` | 识别严格程度。 | 普通情况下推荐。 |
| `mode_thresholds.strict` | `0.45` | 严格模式相似度阈值。 | 调大：更不易把别人识别为目标，但侧脸/模糊脸更容易漏掉；调小：更容易命中，但误识别增加。 |
| `mode_thresholds.balanced` | `0.40` | 平衡模式相似度阈值。 | 调大：结果更少、更保守；调小：结果更多、更灵敏。建议每次以 0.02 为步长调节，例如 0.38、0.42。 |
| `mode_thresholds.sensitive` | `0.35` | 灵敏模式相似度阈值。 | 调大：接近平衡模式；调小：适合远脸、侧脸或暗光，但必须人工抽查误识别。 |
| `sample_fps` | `2.0` | 每秒检测帧数。 | 调大：更容易捕捉短暂出现，定位更细，但检测耗时近似按比例增加；调小：更快，但短于采样间隔的出现可能漏掉。建议 1、2、4 三档调试。 |
| `before_seconds` | `2.0` | 出现前保留时间。 | 调大：保留更多前情，输出更长且更容易与相邻片段相交；调小：输出更短、更紧凑。 |
| `after_seconds` | `2.0` | 出现后保留时间。 | 调大：保留更多后续动作，输出更长且更容易相交；调小：输出更短。 |
| `clip_overlap_strategy` | `trim` | 相邻片段的重叠策略。 | `trim` 无重复；`allow` 允许重复。 |
| `annotate_matched_face` | `false` | 是否将命中人脸画红框。 | 开启后用于人工核对；会逐帧重新识别，导出明显变慢。 |
| `annotation_show_similarity` | `true` | 是否在红框上显示相似度。 | 关闭后画面更简洁，不影响识别本身。 |
| `annotation_box_color_bgr` | `[0,0,255]` | 人脸框颜色，BGR 顺序。 | B、G、R 每项范围 0-255；`[0,0,255]` 红色，`[0,255,0]` 绿色，`[255,0,0]` 蓝色。 |
| `annotation_box_thickness` | `3` | 人脸框线条粗细。 | 调大：脸框更醒目，但会遮挡更多画面；调小：更精细，但小屏幕不明显。通常用 2-4。 |
| `annotation_label_font_scale` | `0.7` | 相似度文字大小。 | 调大：1080p 视频更易看清，但会遮住脸部附近画面；调小：更紧凑。通常用 0.5-1.0。 |
| `annotation_label_thickness` | `2` | 相似度文字笔画粗细。 | 调大：文字更清晰、更粗；调小：更细。通常用 1-3。 |
| `minimum_appearance_seconds` | `0.8` | 最短有效出现时长。 | 调大：过滤偶发误识别和闪过的单帧命中，但可能漏掉短暂出现；调小：更容易保留短出现，也会保留更多噪声。建议以 0.5 秒为步长。 |
| `maximum_gap_seconds` | `3.0` | 命中视为同一次出现的最大间隔。 | 调大：转头、遮挡时不易被拆成多段，但可能把两次真实出现合并；调小：分段更细，但更容易产生很多片段。建议 1-5 秒内调节。 |
| `minimum_face_size` | `48` | 最小人脸像素尺寸。 | 调大：忽略远处小脸，速度稍快、误识别较少；调小：能识别更远的人脸，但准确率下降且耗时增加。建议 32-96。 |
| `detection_threshold` | `0.75` | 人脸检测置信度阈值。 | 调大：只接受更确定的脸框，误检减少但漏检增加；调小：小脸、暗光脸更容易检出，但非人脸误检增加。建议每次 0.05 调整。 |
| `detection_nms_threshold` | `0.3` | 重叠候选脸框的去重阈值。 | 调大：保留更多彼此重叠的候选框，可能重复检测同一张脸；调小：更积极合并重叠框，可能删掉靠近的人脸。通常保持 0.3。 |
| `video_codec` | `libx264` | 输出视频编码。 | H.264 兼容性较好。 |
| `video_crf` | `18` | H.264 输出画质参数。 | 调小：画质更高、文件更大、编码更慢；调大：文件更小、编码可能更快，但细节损失更多。常用范围 18-23。 |
| `video_preset` | `medium` | 编码速度/体积平衡。 | `fast` 更快但文件更大。 |
| `audio_codec` | `aac` | 输出音频编码。 | 保持 AAC。 |
| `overwrite_output` | `false` | 是否覆盖同名文件。 | 保持 false，便于继续任务。 |

## 本地性能结论

本机方案功能可用，适合少量视频、离线处理和人工确认识别效果。HEVC 视频随机抽帧解码较慢，H.264 重编码也占用 CPU；长视频或批量任务更适合放到 RTX 4090 服务器执行。

## CPU 版打码功能（2026 年 9 月 8 日）

CPU 版 `face_clip.py` 已与 GPU 版对齐打码能力：开启 `mask_other_faces` 后，导出阶段逐帧检测所有人脸，目标孩子不打码，其他人脸使用 `dama/cat_kawaii_blink.png` 自动缩放并跟随人脸位置移动。为避免目标孩子因某一帧相似度波动而被误打码，`target_tracking_enabled` 会在短暂未命中时依据上一目标脸的位置、运动方向、框重叠度和尺寸变化进行保守关联；未能严格关联的脸仍会打码。

CPU 版保留 YuNet + SFace 模型，不跳过检测、识别能力；年龄、性别和关键点模型属于 GPU `buffalo_l` 模型包，CPU 版本身不包含这些附加模型。

### CPU 版新增配置

`mask_other_faces`、`mask_image_path`、`mask_scale`、`mask_minimum_size`、`mask_alpha` 控制打码外观；`target_tracking_*` 控制目标脸轨迹保护；`insightface_detection_log`、`detection_log_interval_seconds`、`detection_log_include_similarity` 控制检测日志。参数具体含义与调节建议见 `README.md` 的“关键配置”。

## Windows EXE 打包方案

建议把现有核心做成 Windows 桌面程序：

1. 选择目标人脸图片。
2. 选择单个视频或视频目录。
3. 选择严格、平衡或灵敏模式。
4. 设置前后秒数、去重策略和输出目录。
5. 显示进度、当前视频、片段数量、警告和打开输出目录按钮。

技术建议：使用 Tkinter 或 CustomTkinter；处理任务放在后台线程或子进程；使用 PyInstaller `--onedir` 先打包，携带 FFmpeg、OpenCV DLL、`.models`、默认配置和许可文件。首版需检查磁盘空间、输出权限、有效样本人脸和 FFmpeg 是否可用。

EXE 验收：在未安装 Python 的 Windows 10/11 上，完成 1080p 视频、人脸识别、前后 2 秒、不重复输出、原始分辨率/帧率/音频保留，并验证中断后可继续处理。

### CPU EXE 推荐落地设计

首版采用 PyInstaller `--onedir`，目录内放置 `face_clip.exe`、OpenCV DLL、FFmpeg 可执行文件、YuNet/SFace 模型、默认 `config.json`、`faces`/`dama` 示例目录和第三方许可文件。程序启动时将工作目录设为 EXE 所在目录，避免相对路径失效；配置文件、样本人脸、输入和输出视频均放在 EXE 外部，方便用户更新。

推荐增加一个轻量 GUI 外壳：选择样本人脸、输入目录、输出目录和 JSON 配置，后台启动 `face_clip.exe` 子进程，实时显示扫描/导出日志，并提供停止、继续和打开输出目录按钮。视频处理逻辑继续保留在命令行脚本中，便于排错和自动化。

打包前应固定 Python、OpenCV、NumPy 和 FFmpeg 版本，执行一次干净虚拟机验收；不要把用户的人脸图片、视频或服务器凭据打入安装包。安装包需要检查磁盘空间、FFmpeg 可执行性、模型文件完整性和输出目录写权限。

## 服务器 192.168.4.137 GPU 改造方案

GPU 模型选型、YOLO 比较、部署目录、接口和验收标准详见 `GPU_SERVER_PLAN.md`。

建议由本地 EXE 负责操作，由服务器 RTX 4090 负责计算：

```text
Windows EXE / 本地桌面程序
        |
        | 内网 HTTP 或 HTTPS
        v
192.168.4.137 服务端 API
        |
        +-- 任务队列
        +-- GPU 人脸识别 Worker
        +-- FFmpeg GPU 解码/编码 Worker
        +-- /ssd-data/jobs 文件、日志和结果
```

实施重点：

1. 视频、临时文件、模型和结果全部放到 `/ssd-data`，不要继续占用空间紧张的根分区。
2. 使用 FastAPI 提供创建任务、上传文件、查询状态、下载结果和报告接口。
3. 初期只运行一个 GPU Worker，避免显存和 NVENC 资源竞争。
4. 使用 ONNX Runtime GPU 的 CUDA Execution Provider 或经验证的 GPU 人脸模型，重新校准阈值。
5. FFmpeg 启用 NVDEC/NVENC，核对裁剪时间、分辨率、帧率和音频是否与本地版本一致。
6. 返回剪辑、报告和日志的 ZIP 包，并设置任务文件自动清理策略。
7. 内网服务也要鉴权；不得把服务器密码、SSH 密码和人脸数据写入代码、配置、EXE 或日志。

上线前必须用同一批视频比较本地和服务器：命中片段数量、误识别、输出规格、端到端处理时间和 `/ssd-data` 磁盘使用。GPU 可显著提升推理速度，但整体速度仍受到视频解码、随机寻帧、磁盘和编码速度影响。
